# Changelog

All notable changes, newest first. Versions follow `MAJOR.MINOR.PATCH`:
until 1.0, MINOR goes up for each approved feature.

## Unreleased

- An empty frame when there are no spectra (asked for: "Hide all" on the website should leave the figure empty, not keep one spectrum). `plot` and `panels` draw a collection of 0 spectra, of any kind, as an empty frame: the box, title, axis labels, marks, notes and shaded ranges, the x axis over the same range (and margin) as with the lines, no numbers on y. A wrong `emphasize` number is still refused. Service: `/figure` (plain data and panels) accepts `"Y": []`; every other request answers 422 `data has no spectra ("Y" is empty); send at least one row of Y.` Before: an empty `Y` failed with a shape message. 5 new tests. Documentation pictures unchanged.

- The colour of each spectrum, from the toolkit itself. New `stk.line_colors(n, style, groups=None, **settings)` gives the colour (`"#rrggbb"`) plot draws each of n spectra in: the palette in order, the colour map (`cmap`) for more than 10, one colour per group (as `color_by="group"`; spectra without a group share one), then `line_color` and colour letters in `line_format`. Service: `POST /colors` (`{"n", "style", "settings", "groups"}` -> `{"colors": [...]}`), so the website shows each spectrum's colour before drawing without keeping its own copy of the rule; the Worker allows the new request (`worker/stk-worker.js`, redeploy needed). 2 new tests (every case checked against the colours plot actually draws), 2 new Worker checks. Documentation pictures unchanged.

- Website route, part 1 (roadmap A1; `docs/website.md`). **Secret key:** with `STK_API_KEY_FILE` (or `STK_API_KEY`) set, every endpoint but `/health` needs the key in the `X-STK-Key` header (compared in constant time) and answers 401 without it; `/docs` gets an "Authorize" button. The Docker image sets `STK_REQUIRE_KEY=1` (no start without a key) and `STK_MAX_UPLOAD_MB=95` (under Cloudflare's 100 MB). Without a key set (your own computer) nothing changes. **Worker** `worker/stk-worker.js` for `cheminations.com/api/stk/*`, in the style of the spectra Worker: only pages of the site, only the toolkit's 9 requests each with its own method, form or JSON as each expects, 95 MB at most, 120 requests a minute per visitor, adds the key; `options` and `example` kept for an hour (and up to 7 days when the VM is down), everything else never kept; pictures and big answers streamed through; the toolkit's messages passed on, a wrong key treated as "temporarily unavailable". Tested with `worker/test/` (31 checks in a browser against a local toolkit), then live after setup (`docs/website.md`, "Tested live"). 2 new tests for the key.

- See inside .mat files (asked for: see the variables and their sizes, to choose what to plot). New `stk.mat_variables(path)`: one row per variable (name, size as MATLAB's size(), vector or matrix, min and max, whether it can be an x axis), every x / y pair that fits (how many spectra and points, columns or rows), the pair `load` uses (`"chosen"`) and what was skipped; when `load` cannot guess, the table still comes back with `"problem"`. The same table is kept in `meta["variables"]` after loading (it was only {name: shape} before). Choosing only y now also finds the fitting x vector when y is a vector (before: point number), with a note saying which x was used. Service: `/load` answers `"variables"` (null for files other than .mat), and `/load` and `/process-file` take `x` and `y` (variable names; empty = guessed). `Recipe.apply` and `run` take `load_options`. 4 new tests; the `/load` field-list test now includes `"variables"`.

- Feature 1c, instrument files. **Renishaw WiRE .wdf** (new `io/wdf.py`, our own reader, no extra package): single spectra, series and maps; x turned round to rising; map positions in `.positions` (X, Y in µm, one row per spectrum, kept through select, drop and processing) with `meta["position_labels"]`; the grid in `meta["map"]`; instrument, title, laser, accumulations, start and end, the time of each spectrum and the white-light image in `meta`. Stopped measurements give the spectra measured; damaged files, files without spectra and detector images give clear messages. **Shimadzu UVProbe .spc** (UV-Vis; new `io/shimadzu.py` on our own compound-file reader `io/cfb.py`, no extra package): wavelength in nm turned round to rising, y unit from the method's Measuring Mode (e.g. Absorbance), instrument, software and every method setting in `meta`; several data sets give a collection or a list. Old .xls files still go to the spreadsheet reader; a .spc that is not a UVProbe file (e.g. Galactic SPC) says so clearly, instead of a spreadsheet error. **EnSpectr .esp**: the `#proc_cfg={...}` line was taken as the column titles (x unit `proc_cfg={"base_fit":`); a first cell with "=" is now always a setting, and settings written as JSON (`#exp_cfg={...}`) are kept as dicts. **Service:** data answers have `"positions"` (null when none) and `"position_labels"`, and requests may send them back. 14 new tests (7 in the new `tests/test_wdf.py`, which writes its own small .wdf files; 6 in the new `tests/test_spc.py`, which writes its own small compound files; 1 for .esp); the `/load` field-list test now includes the two new fields.

- Test fix: `test_example_spectra_for_the_preview` allowed only 2 pixels between the 60-dpi preview and half of a 120-dpi figure, but `tight` trims the white edge at each dpi on its own (publication style: 336 vs 676 px wide). It now allows 1 % (at least 2 pixels). No code change.
- Saved styles and live preview, the toolkit and service part (wish list 7, items 15 A and 16; the website page comes next, after approval of the website changes). **Style files, version 1:** `stk.save_style` now writes only the settings that differ from the preset, plus `"type": "spectrum-toolkit style"`, `"version"`, `"name"`, `"saved"` (date), `"toolkit"` (version) and `"preset"`; settings added later get their default, and an improved default reaches the file too. `only_changed=False` writes every setting; `name=` names the style (default: the file name). New `stk.style_file(...)` gives the same contents as a dict without saving. `get_style` (and every `style=`) reads these files and their contents as a dict; older files (every setting, no `"type"`) still load; a file from a newer version says so and asks for an update. The key is `"type"`, not `"format"`, because `format` is already a setting (the figure's file type). **`/style-check`** also answers `"file"` (the style file to download; `"name"` in the request names it), `"renamed"` (older setting names, e.g. `ticks` -> `tick_direction`, with a warning) and `"skipped"`: with `"lenient": true`, setting names this toolkit does not know are left out and listed instead of a 422. `/figure` takes a style file's contents as `"style"` too. **`GET /example`**: three made-up example spectra (new `stk.example()`, the ones the documentation pictures use), ready to send to `/figure`, for the preview before a file is loaded. Earlier figures and all 21 documentation pictures look exactly as before (checked pixel by pixel). 5 new tests.
- Groups and before/after panels (wish list 7, item 12 h and g). **Groups** (new `spectrum_toolkit.groups`): which sample each spectrum belongs to is stored with the data (`c.groups`, one label per spectrum; `s.group` for one spectrum) and follows the spectra through every step, `select`/`drop` and `combine`. Five ways to set them: `c.set_groups({"CV": range(0, 14), ...})` (numbers or names), a list with one label per spectrum, `"name"` ("CV 1", "CV_2" -> CV; words such as "Spectrum" or "Spot" are not groups), `pattern=r"..."`, and `"file"` (`stk.combine(..., groups="file")`); `rename=` renames. `c.suggest_groups()` proposes groups with the reason and never guesses from names that only number the spectra; `c.by_group()` splits. Plots: `color_by="group"` (one colour and legend entry per group; with `kind="mean"` one mean per group) and `stk.panels(c, by="group", kind=...)`. **Before/after panels**: `{"data": before, "after": after, "kind": "compare"}` in `stk.panels`, with the "removed" strip under the panel so boxes stay lined up and `share_x` works; short default title "baseline (airpls)". `stk.compare` takes `ax=`; on its own figure it looks exactly as before. Website: data carries `"groups"`, `POST /groups` proposes or sets them, `/figure` takes `"color_by"`, `"by": "group"` and compare panels. Two new pictures in `docs/plotting.md`. 27 new tests (22 in the new `tests/test_groups.py`, 3 for plots, 2 for the website).
- Web service, wish list 7, item 15 (service part of "C plus A"): `POST /style-check` takes `"style"` (a preset name or a dict, e.g. the contents of a saved style file) and `"settings"`, and answers `"style"` (every setting, ready to save and load again), `"changed"` (what differs from the defaults) and `"warnings"` (fonts not installed). Wrong settings answer 422 with the usual message. Safety fix on `/figure`: `"style"` given as a file name (e.g. `"x.json"`) used to make the server open that file; the service now accepts only a preset name or a dict. 3 new tests. Also (approved on the decision card): settings ending in `_width`, `_size` or `_length` below 0 now give a clear message (`line_width must be 0 or more; got -1.`); before, they were accepted silently. 5 new test cases.
- Plotting, round 8 (wish list section 7, item 12, panels a to f): `stk.panels` (and `"panels"` on `/figure`) takes `layout` as text, such as `"AA;BC"` (rows split by `;`, the same letter for a panel across places, `.` for an empty place; each panel must fill a rectangle), and `widths` / `heights` (one number per column / row). New settings: `panel_spacing_x` and `panel_spacing_y` (the space between columns and between rows, each on its own; None follows `panel_spacing`), `panel_legend` ("each", or one legend for the whole figure at "figure top", "figure bottom" or "figure right"; under the figure title when there is one), `panel_shared_labels` (one x and/or y axis title for the whole figure; `xlabel` / `ylabel` on panels set the text) and `panel_colorbar` ("shared": one colour bar with the same colour range for all image panels). Every new option is off by default, so earlier figures look exactly as before (checked pixel by pixel). 389 settings, each checked. Two new pictures in `docs/plotting.md`. 5 new tests.
- Plotting, round 7 (wish list section 7, item 1): `x_range` and `y_range` fix the axis limits (either end may be None for automatic; the direction follows `invert_x`), and `x_margin` / `y_margin` set the automatic white space around the data (0.05 as before). `y_range` wins over the y fit of `region`; peak labels of bands it cuts off stay at the top of the box. Works for lines, stack, mean, image and compare. 384 settings, each checked. One new picture, 1 new test. Earlier figures look exactly as before.
- Plotting, round 6 (wish list section 7, items 2 to 14; item 1 waits for approval, 15 and 16 for discussion): `x_log`/`y_log`; a second axis on top (`top_axis`: absolute wavelength for `top_axis_laser`, or a scale and offset) and on the right (`right_axis`), styled by the top/right tick settings; `cut_marks` breaks the line where `cut` removed points and draws // on the box; `line_names` writes each name next to its line, with or without the legend; `scale_bar` (stands past the names when both are on one side); `mean_band` (std, 2std, minmax, ci95, none) with its colour and transparency; for images `color_limits`, `colorbar` options and `image_y="name"` (spectrum numbers are now whole numbers only); `plot(notes=[...])` for free text with arrows (`note_...` settings, per note too); `plot(inset=[lo, hi])` for a zoomed view (`inset_...` settings; a legend at "best" keeps clear of it); `stk.panels` for several plots in one figure with letters (`panel_letter_...`, `panel_spacing`, `layout`, `share_x`, `share_y`, a figure `title`); `tight` for saving. On `/figure`: `notes`, `inset`, and `"panels": [...]` in place of `"data"`; an `X-Warning` header names fonts that are not installed on the server. 380 settings, each checked by `scripts/check_plot_settings.py`. Seven new pictures in `docs/plotting.md`. 11 new tests. Earlier figures look exactly as before (checked pixel by pixel).
- Plotting, round 5 (wish list points 2 and 3): marks, peak labels and highlighted ranges have their own settings. Marks: `mark_color`, `mark_style`, `mark_width`, `mark_alpha`, `mark_span` (full height, up to the spectrum, or a short line above it); one mark can have its own look (`marks={1620: {"label": "C=C", "color": "red"}}`). Peak labels: `peak_label_format`, `peak_sensitivity`, `peak_spectra` (first, all or chosen spectra), `peak_line` with its own colour, type, width and transparency, and `peak_label_color: "line"`. Highlights: `highlight_color`, `highlight_alpha`, `highlight_hatch` (stripes for print), `highlight_edge_color`/`_width`/`_style`, and per range its own label and look (`{"range": [1570, 1640], "label": "G band", "color": "blue"}`); spikes: `spike_color`, `spike_alpha` (also in compare). Text on the plot (mark, peak and highlight labels) each with colour, transparency, size, weight, italics, font, rotation, position (above the box or above the spectrum), distance and a box behind the text; `label_overlap` moves overlapping labels apart; math text such as `$\nu_{as}$` works. 299 settings, each checked by `scripts/check_plot_settings.py`. Two new pictures in `docs/plotting.md`. 6 new tests. Figures look as before (checked pixel by pixel), except that labels which overlapped are now moved apart (`label_overlap="keep"` gives the old placement).
- Plotting, round 4 (wish list point 1, spectral lines): `line_color`, `line_alpha`, `line_format` (MATLAB codes such as `"o-"`, `"*--"`, `"."`, `"r:"`), marker settings (`marker_color`, `marker_fill` with `"none"` for hollow, `marker_alpha`, `marker_edge_width`, `marker_every`), `fill` under each line (`fill_color`, `fill_alpha`), `zero_line_alpha`; from the cross-check against the agreed wish list, also `x_ticks_at`/`y_ticks_at` (exact tick positions), `x_tick_count`/`y_tick_count` (about how many ticks), `legend_hide` (leave entries out) and `legend_location` "outside top" / "outside bottom" ("outside right" as before); and the palettes `tab20` and `dark` or any colour map name for `colors`. The line settings take one value or a list, one per spectrum. `plot(emphasize=[...])` brings chosen spectra forward (`emphasize_width`, `faded_alpha`). On `/figure`, `emphasize` goes at the top level and the RGB/CMYK choice is now `color_mode` (the old `color` still works). 238 settings, each checked by `scripts/check_plot_settings.py`, plus a check that a list changes only its own spectrum. Three new pictures in `docs/plotting.md`. 19 new tests. Figures with default settings look exactly as before (checked pixel by pixel).
- Plotting, round 3 (wish list points 4 and 6, `docs/plotting_wishlist.md`): every part of the box, ticks, tick labels, axis labels, title and legend has its own settings (219 settings, up from 40). Ticks and box can be set per side (`top_tick_length`, `right_tick_color`, `left_box_width` ...) and per axis (`x_tick_direction`, `y_tick_label_size` ...), each falling back to the general setting; transparency (`_alpha`) for every colour; legend title, columns, order, legend box and fill; every colour accepts names, hex, RGB (0-1 or 0-255), RGBA and `cmyk(...)` (`stk.to_rgba`). Wrong values give a clear error naming the setting. `ticks` is now `tick_direction` (the old name still works). Reference `docs/plotting.md` with example pictures, written by `scripts/make_plotting_docs.py`; a test fails if a setting is not documented. `scripts/check_plot_settings.py` changes every setting one at a time and confirms each one changes the saved figure, that per-side settings act only on their own side, and that wrong values give a clear message. Setting descriptions use the same words throughout (transparency, true or false, line type, in points). 17 new tests. Figures with default settings look the same as before (checked pixel by pixel), except that compare's title is 1 point larger (it now follows `title_size`).
- Feature 10: web service `spectrum_toolkit.api` (FastAPI: health, options, load, process, process-file, figure; `summary_only` on load and process-file leaves out the numbers for big files; the process answers start with `"kind": "lines"` so they can be pasted into figure as they are; a wrong `highlight` answers 422, and spikes cut off by trim are no longer shaded) as the optional extra `[api]`, and a `Dockerfile` that runs it. Tested in the built image on every file in data/. 20 new tests (`tests/test_api.py`); `conftest.py` skips the module's doctests when FastAPI is not installed.
- Feature 9: recipes (`stk.Recipe`, `stk.apply`, `.apply()` methods): from history or step by step, saved as JSON with every setting, re-applied to data or files; `run` keeps each step. 11 new tests, notebook 11.
- Bug fixes from running everything on all real data (`scripts/check_all_data.py`): files are closed after loading; long-format map files are recognised with a clear message instead of being misread; repeated x values give a clear error in derivative, spline smoothing, rollingball and snip; clearer message for `normalize("band")` without a band.

- Feature 8, round 2: figure styles (`spectrum_toolkit.style`): 40 named settings, presets clean / publication / matlab, `stk.set_style`, `stk.save_style` (JSON), `stk.get_style`; `stk.export` (png, tiff, jpg, pdf, svg, eps; dpi; RGB or CMYK; folder and name); `stk.scatter` (grouped points like gscatter); `peaks=` and `marks=` labels. 18 new tests, notebook 10 with a style editor.

- Feature 8: `stk.plot` (kinds lines, stack, mean, image; region, styles "clean"/"publication", save) and `stk.compare` (before/after view of a step with a "removed" panel; spikes shaded, baseline drawn). Also as `.plot()` methods. matplotlib is now an optional extra: `spectrum-toolkit[plot]`. 10 new tests, notebook 09.

- Benchmarks: `benchmarks/` scripts compare the methods of every feature on simulated spectra (and the real repeats in data/) and write `docs/benchmarks.md`. Rerun with `uv run python benchmarks/run_all.py`. The comparison tables moved there from the roadmap.

- Feature 7: `derivative` (1st and 2nd) with 4 methods (savgol default, gaussian, smoothing spline, gradient); default window/order/sigma chosen per n from the benchmark; uneven x handled. 13 new tests, notebook 08.

- Feature 6: `normalize` with 10 methods (snv default, max, minmax, area, vector, robust snv, band/internal standard, msc, emsc, pqn); `region=` for one-factor methods; `reference=` for msc/emsc/pqn. 16 new tests, notebook 07.

- Feature 5: `smooth` with 7 methods (savgol default, whittaker, automatic smoothing spline, gaussian, moving, median, fourier); 11 new tests.

- Feature 4: `baseline` and `find_baseline` with 8 methods (asls as in baseline.m, iasls, arpls, airpls, modpoly, imodpoly, rollingball, snip); 14 new tests.

- Feature 3: `despike` with methods "single" (default), "compare" (repeats) and "kalkan" (port of spikeRemoval.m); every spike reported. 10 new tests, including the real cosmic rays in CV10-4M.xlsx.

- Feature 2: `trim`, `cut`, `select`, `drop` (also as methods), `stk.combine` for many files with an x-axis check (`stk.check_axes`); interpolation only with `interpolate=True`. interpolation methods linear, quadratic, cubic, pchip, akima; `stk.resample`. 24 new tests.
- Loader: axis titles like "wavenumber" or "Intensity" are no longer used as spectrum names.

- Feature 1b: `stk.load()` reads MATLAB .mat files, finding the x axis and spectra by shape (any variable names); `x=`/`y=` to choose by name. 12 new tests.
- Feature 1: `stk.load()` for text files and Excel (.xlsx, .xls), with layout detection, decimal commas, headers, metadata and a fast path for large files.
- New dependencies: openpyxl, xlrd.
- Notebook `01_loading.ipynb`; 23 new tests (awkward files, large file, real data).
